# План решения проблемы с отображением времени +3 часа

## Проблема
На сайте отображается время с отклонением +3 часа, несмотря на настройку `TIME_ZONE = 'Europe/Moscow'`.

## Текущие настройки
- `TIME_ZONE = 'Europe/Moscow'` (UTC+3)
- `USE_TZ = True` 
- `MIDDLEWARE` не содержит `TimezoneMiddleware`

## Диагностика
Django с `USE_TZ=True`:
1. Хранит даты в UTC в базе данных
2. При отображении конвертирует в `TIME_ZONE` (Europe/Moscow)
3. Для корректной конвертации нужен `TimezoneMiddleware`

## Возможные решения

### Вариант 1: Включить TimezoneMiddleware (Рекомендуется)
**Плюсы:**
- Соответствует best practices Django
- Автоматическая конвертация времени для всех пользователей
- Правильная работа с DST (переход на летнее время)

**Минусы:**
- Требует настройки middleware

**Изменения:**
1. Добавить `TimezoneMiddleware` в `MIDDLEWARE` в settings.py
2. Middleware будет активировать timezone на основе сессии или деактивировать (используя TIME_ZONE по умолчанию)

### Вариант 2: Отключить USE_TZ
**Плюсы:**
- Простое решение
- Даты хранятся и отображаются в Europe/Moscow напрямую

**Минусы:**
- Не рекомендуется Django
- Проблемы с DST переходами
- Менее безопасно для будущего

**Изменения:**
- Установить `USE_TZ = False` в settings.py

## Рекомендация
**Использовать Вариант 1** - включить `TimezoneMiddleware`, так как это соответствует best practices Django и обеспечивает правильную работу с временными зонами.

## Конкретные шаги
1. Добавить middleware класс в `MIDDLEWARE` в `pcontrol/settings.py`
2. Middleware будет устанавливать timezone на основе TIME_ZONE настройки по умолчанию
3. Проверить корректность отображения времени на сайте
